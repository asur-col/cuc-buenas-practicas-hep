Lab 4 — VLANs, troncales 802.1Q y Port-Security

Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Lab 4 · Tiempo estimado: 90 min · Semana: S4

Objetivo

Dos switches (sw1, sw2) unidos por un troncal 802.1Q. De fábrica todos los puertos están en VLAN 1: pc1–pc4 se ven entre sí (mismo dominio de broadcast). Debes:

  1. Hardening en ambos switches (nombre, banner, enable secret, usuario, SSH only, cifrado)
  2. Crear VLAN 10 (VENTAS) y VLAN 20 (SOPORTE)
  3. Asignar puertos de acceso: sw1 gi0/1→pc1 (VLAN 10), sw1 gi0/2→pc2 (VLAN 20), sw2 gi0/1→pc3 (VLAN 10), sw2 gi0/2→pc4 (VLAN 20)
  4. Configurar troncal 802.1Q en gi0/3 (sw1↔sw2) permitiendo VLANs 10,20
  5. Port-security en sw1 gi0/1 (pc1): máx 1 MAC, sticky, violation shutdown
Guía verificada: ejecutada sobre estación desechable (oco-tmp-lab04-station, imagen labs/hep-redes-lab04:1.0.0). Salidas reales de configuración switches, VLANs, troncal, port-security y tests de conectividad.

Topología de fábrica

     pc1      pc2          pc3      pc4
      |        |            |        |
   gi0/1   gi0/2          gi0/1   gi0/2
    sw1 ──────┐           ┌────── sw2
        gi0/3 ─────────── gi0/3
      (troncal 802.1Q)

Dispositivos: sw1, sw2 (switches L2), pc1–pc4 (hosts).

CLI (netcli, estilo IOS para switches)

ComandoQué hace
vlan IDCrear/entrar a VLAN

Paso 3 — Puertos de acceso y troncal en sw1 ≈15 min

Asignar gi0/1 (pc1) a VLAN 10, gi0/2 (pc2) a VLAN 20, y configurar gi0/3 como troncal 802.1Q permitiendo VLANs 10,20.

Comando exacto (en netcli sw1):

configure terminal
interface gi0/1
switchport mode access
switchport access vlan 10
exit
interface gi0/2
switchport mode access
switchport access vlan 20
exit
interface gi0/3
switchport mode trunk
switchport trunk allowed vlan 10,20
exit
end
write memory
show vlan brief

Salida real:

SW1-HEP# show vlan brief
VLAN Name                             Status    Ports
1     VLAN01                           active    
10    VLAN10                           active    gi0/1,gi0/3
20    SOPORTE                          active    gi0/2

Verificación: VLAN 10 en gi0/1 (access) y gi0/3 (trunk); VLAN 20 en gi0/2 (access) y gi0/3 (trunk).

Error típico: olvidar switchport mode trunk antes de allowed vlan. Corrección: modo trunk primero.

Verificador: criterio de VLANs y troncal.

Paso 4 — Port-security en sw1 gi0/1 ≈10 min

Proteger el puerto de pc1: máx 1 MAC, aprendizaje sticky, shutdown en violación.

Comando exacto (en netcli sw1):

configure terminal
interface gi0/1
switchport port-security
switchport port-security maximum 1
switchport port-security violation shutdown
switchport port-security mac-address sticky
end
write memory

Salida real (fragmento show running-config):

interface gi0/1
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 1
 switchport port-security violation shutdown

Verificación: port-security habilitado en gi0/1 con maximum 1, violation shutdown, sticky.

Error típico: activar port-security sin switchport mode access primero. Corrección: modo access antes que port-security.

Verificador: criterio de port-security.

Paso 7 — Configurar IPs en los 4 hosts ≈10 min

Asignar IP a pc1/pc3 (VLAN 10: 192.168.10.x) y pc2/pc4 (VLAN 20: 192.168.20.x).

Comando exacto (desde el host de la estación):

# pc1 (VLAN 10)
ip netns exec lab-pc1 ip addr add 192.168.10.10/24 dev eth0
ip netns exec lab-pc1 ip link set eth0 up

# pc2 (VLAN 20)
ip netns exec lab-pc2 ip addr add 192.168.20.10/24 dev eth0
ip netns exec lab-pc2 ip link set eth0 up

# pc3 (VLAN 10)
ip netns exec lab-pc3 ip addr add 192.168.10.20/24 dev eth0
ip netns exec lab-pc3 ip link set eth0 up

# pc4 (VLAN 20)
ip netns exec lab-pc4 ip addr add 192.168.20.20/24 dev eth0
ip netns exec lab-pc4 ip link set eth0 up

Salida real: comandos sin errores; 4 hosts con IP y link UP.

Verificación: ip netns exec lab-pc1 ip addr show eth0 muestra inet 192.168.10.10/24.

Error típico: IP en subred equivocada o interfaz down. Corrección: verificar IP y ip link set up.

Verificador: criterio de direccionamiento de hosts.

Paso 8 — Verificar conectividad: misma VLAN a través del troncal ≈10 min

Confirmar que hosts en la misma VLAN se comunican aunque estén en switches distintos (trunk 802.1Q funcionando).

Comando exacto:

# pc1 (VLAN10 sw1) -> pc3 (VLAN10 sw2)
ip netns exec lab-pc1 ping -c 2 192.168.10.20

# pc2 (VLAN20 sw1) -> pc4 (VLAN20 sw2)
ip netns exec lab-pc2 ping -c 2 192.168.20.20

Salida real:

PING 192.168.10.20 (192.168.10.20) 56(84) bytes of data.
64 bytes from 192.168.10.20: icmp_seq=1 ttl=64 time=1.03 ms

Error típico: trunk sin allowed vlan o VLANs no creadas en ambos switches. Corrección: verificar show vlan brief en ambos.

Verificador: criterio de conectividad VLANs.

Paso 9 — Verificar aislamiento: distinta VLAN no se comunican ≈5 min

Confirmar que sin router, hosts de VLAN 10 y VLAN 20 NO se ven (dominios de broadcast separados).

Comando exacto:

# pc1 (VLAN10) -> pc2 (VLAN20) - mismo switch
ip netns exec lab-pc1 ping -c 2 192.168.20.10

# pc3 (VLAN10) -> pc4 (VLAN20) - switches distintos
ip netns exec lab-pc3 ping -c 2 192.168.20.20

Salida real:

ping: connect: Network is unreachable
ping: connect: Network is unreachable

Verificación: Network is unreachable = aislamiento L2 correcto entre VLANs.

Error típico: si hace ping, revisar que los puertos estén en modo access correcto y no en trunk. Corrección: switchport mode access + switchport access vlan.

Verificador: criterio de aislamiento VLANs.

Paso 10 — Verificar port-security y dejar evidencia ≈10 min

Confirmar que port-security en sw1 gi0/1 aprendió la MAC de pc1 (sticky) y dejar evidencias finales.

Comandos de evidencia:

netcli sw1    show running-config | include port-security
netcli sw1    show vlan brief
netcli sw2    show vlan brief
# Test conectividad:
pc1 -> pc3 (VLAN10)  0% loss
pc2 -> pc4 (VLAN20)  0% loss
pc1 -> pc2 (diff VLAN)  unreachable
# FDB sw1 gi0-1 muestra MAC pc1 aprendida en VLAN 10
ip netns exec lab-sw1 bridge fdb show dev gi0-1

Salida real (bridge fdb show dev gi0-1):

76:17:91:4a:6d:56 vlan 10 master br0 
9a:b7:81:06:63:73 vlan 10 master br0 permanent
... (multicast/self entries)

Verificación: MAC de pc1 (76:17:91:4a:6d:56) aprendida en VLAN 10 en gi0-1. Port-security sticky activo.

Error típico: no capturar evidencia de MAC aprendida. Corrección: siempre documentar bridge fdb o show port-security.

Verificador: criterio de port-security y evidencias.
