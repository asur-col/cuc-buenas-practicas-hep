Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Valor: 5,0 (5 criterios × 1,0) · Tiempo estimado: 90 minutos · Individual.

Objetivo

r1 es el router-firewall de una red con tres zonas: la WAN (el proveedor isp), la LAN interna (pc1) y la DMZ (srv1, con un servidor web que será público). El ISP viene configurado de fábrica —IP 10.0.0.2, servidor web y rutas de vuelta a tu LAN y tu DMZ—: es decir, si no filtras, puede entrar. Tu trabajo: direccionar la red y aplicar la política de zonas con ACLs.

Topología

                WAN 10.0.0.0/30
   isp 10.0.0.2 ──── eth0 r1
                        │ eth1 ─── LAN 192.168.10.0/24 ─── pc1 (192.168.10.10)
                        │ eth2 ─── DMZ 172.16.5.0/24 ─── srv1 (172.16.5.10, web en 80)

La política de zonas (lo que piden los criterios)

ZonaPuedeNo puede
LAN (pc1)HTTP/HTTPS a la DMZ · HTTP/HTTPS/DNS a la WAN · ICMP de diagnósticoSSH ni nada más a la DMZ
DMZ (srv1)Responder conexiones ya establecidasIniciar hacia la LAN o la WAN
WAN (isp)Responder conexiones ya establecidasIniciar hacia la LAN o la DMZ

netcli r1
r1> enable

r1(config)# interface eth0
r1(config-if)# ip address 10.0.0.1 255.255.255.252
r1(config-if)# no shutdown
r1(config-if)# exit
r1(config)# interface eth1
r1(config-if)# ip address 192.168.10.1 255.255.255.0
r1(config-if)# no shutdown
r1(config-if)# exit
r1(config)# interface eth2
r1(config-if)# ip address 172.16.5.1 255.255.255.0
r1(config-if)# no shutdown
r1(config-if)# exit

Y los hosts (consola Linux):

netcli pc1
[pc1] $ ip addr add 192.168.10.10/24 dev eth0
[pc1] $ ip route add default via 192.168.10.1
[pc1] $ exit
netcli srv1
[srv1] $ ip addr add 172.16.5.10/24 dev eth0
[srv1] $ ip route add default via 172.16.5.1
[srv1] $ exit

Paso 2 — Los ACLs

Las ACLs extendidas se crean con nombre, se llenan de reglas y se aplican a la entrada de cada zona (ip access-group … in):

r1(config)# ip access-list extended ACL-LAN-IN
r1(config-ext-nacl)# permit tcp any 172.16.5.0 0.0.0.255 eq 80
r1(config-ext-nacl)# permit tcp any 172.16.5.0 0.0.0.255 eq 443
r1(config-ext-nacl)# permit tcp any 10.0.0.0 0.0.0.3 eq 80
r1(config-ext-nacl)# permit tcp any 10.0.0.0 0.0.0.3 eq 443
r1(config-ext-nacl)# permit udp any 10.0.0.0 0.0.0.3 eq 53
r1(config-ext-nacl)# permit icmp any any
r1(config-ext-nacl)# exit

La máscara es comodín (wildcard), como en IOS: 0.0.0.255 = «los 24 bits de red me importan». Al final de toda ACL hay un deny ip any any implícito — si algo no está permitido explícitamente, se cae.

r1(config)# ip access-list extended ACL-WAN-IN
r1(config-ext-nacl)# permit tcp any any established
r1(config-ext-nacl)# exit
r1(config)# ip access-list extended ACL-DMZ-IN
r1(config-ext-nacl)# permit tcp any any established
r1(config-ext-nacl)# exit

established deja pasar solo las respuestas de conexiones que nacieron adentro: la DMZ y la WAN pueden contestar, nunca iniciar.

Paso 3 — Aplicar cada ACL en su zona

r1(config)# interface eth1
r1(config-if)# ip access-group ACL-LAN-IN in
r1(config-if)# exit
r1(config)# interface eth0
r1(config-if)# ip access-group ACL-WAN-IN in
r1(config-if)# exit
r1(config)# interface eth2
r1(config-if)# ip access-group ACL-DMZ-IN in
r1(config-if)# exit
r1(config)# end
r1# write memory

Comprueba tú antes que el servidor

[pc1] $ busybox wget -q -O- http://172.16.5.10/     # OK: la web de la DMZ
[pc1] $ busybox nc -z -w 3 172.16.5.10 22 && echo ENTRÓ || echo BLOQUEADO
[pc1] $ busybox wget -q -O- http://10.0.0.2/        # OK: sale a la WAN
$ ip netns exec lab-isp ping -c1 192.168.10.10      # debe FALLAR
$ ip netns exec lab-srv1 ping -c1 192.168.10.10    # debe FALLAR
$ revisar

El verificador hace estas mismas pruebas con tráfico real (y para el SSH levanta él mismo un servidor en el 22 para que no te salves con un «connection refused» de un puerto sin nada escuchando).

Errores típicos

  • Crear el ACL y no aplicarlo (ip access-group): las reglas existen pero no filtran.
  • Olvidar established en WAN/DMZ: la LAN navega pero nunca recibe las respuestas.
  • Poner la wildcard como máscara de red (255.255.255.0 en vez de 0.0.0.255): la regla no coincide con nada.
  • Permitir ip any any en la LAN: pasa todo y el criterio del SSH se pierde.
