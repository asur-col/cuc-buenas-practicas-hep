Lab 3 — ACLs y zonas (LAN, DMZ y WAN)

Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Lab 3 · Tiempo estimado: 75 min · Semana: S3

Objetivo

r1 es el firewall de una red con tres zonas: WAN (isp), LAN (pc1) y DMZ (srv1 con web). El ISP viene configurado de fábrica y SABE llegar a la LAN y a la DMZ: sin ACLs puede entrar. Debes direccionar r1/pc1/srv1 y aplicar la política de zonas con ACLs:

  • LAN → DMZ: solo web (tcp 80)
  • LAN → WAN: todo
  • DMZ → LAN/WAN: no puede iniciar conexiones (solo tráfico de retorno established)
  • WAN → LAN/DMZ: no puede iniciar conexiones
Guía verificada: ejecutada sobre estación desechable (oco-tmp-lab03-station, imagen labs/hep-redes-lab03:1.0.0). Salidas reales de configuración de r1, ACLs y tests de conectividad.

Topología de fábrica

             (WAN)                      (LAN)                      (DMZ)
        isp eth0 ========= eth0 r1 eth1 ========= pc1   r1 eth2 ========= srv1
        10.0.0.2/30                    192.168.10.1/24             172.16.5.1/24
        (pre-configurado: IP, rutas, web)                       (servidor web puerto 80)

Dispositivos: r1 (router/firewall), isp (host WAN, pre-configurado), pc1 (host LAN), srv1 (host DMZ con servidor web).

CLI (netcli, estilo IOS)

ComandoQué hace
ip access-list extended NAMEACL extendida
permit tcp src wildcard dst wildcard eq 80permite tráfico TCP web
permit tcp ... establishedpermite tráfico de retorno (conexiones establecidas)
deny ip ...deniega tráfico IP
show access-listsmuestra las ACLs configuradas
ip access-group NAME inAplica ACL en tráfico de entrada de una interfaz

Paso 4 — Crear ACLs de política de zonas ≈15 min

Crear 6 ACLs extendidas con orden correcto: en ACLs de entrada WAN, la regla established DEBE ir antes que el deny.

Comando exacto (en netcli r1):

ip access-list extended ACL-LAN-DMZ
permit tcp 192.168.10.0 0.0.0.255 172.16.5.0 0.0.0.255 eq 80
permit ip 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.3
deny ip 192.168.10.0 0.0.0.255 172.16.5.0 0.0.0.255
exit
ip access-list extended ACL-LAN-WAN
permit ip 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.3
exit
ip access-list extended ACL-DMZ-LAN
permit tcp 172.16.5.0 0.0.0.255 192.168.10.0 0.0.0.255 established
deny ip 172.16.5.0 0.0.0.255 192.168.10.0 0.0.0.255
exit
ip access-list extended ACL-DMZ-WAN
deny ip 172.16.5.0 0.0.0.255 10.0.0.0 0.0.0.3
exit
ip access-list extended ACL-WAN-LAN
permit tcp 10.0.0.0 0.0.0.3 192.168.10.0 0.0.0.255 established
deny ip 10.0.0.0 0.0.0.3 192.168.10.0 0.0.0.255
exit
ip access-list extended ACL-WAN-DMZ
permit tcp 10.0.0.0 0.0.0.3 172.16.5.0 0.0.0.255 established
deny ip 10.0.0.0 0.0.0.3 172.16.5.0 0.0.0.255
exit

Verificación: show access-lists muestra las 6 ACLs. Clave: en ACL-WAN-LAN y ACL-WAN-DMZ la regla established está en línea 10 (antes que deny).

Verificador: criterio de ACLs y política de zonas.

Paso 5 — Aplicar ACLs a las interfaces ≈10 min

Aplicar cada ACL en la interfaz de entrada correspondiente: eth1 (LAN), eth2 (DMZ), eth0 (WAN).

Verificación: ip access-group aplicado en eth1, eth2 y eth0 con las ACLs correctas.

Error típico: aplicar la ACL en la interfaz equivocada o en dirección out en vez de in. Corrección: verificar dirección in en cada interfaz.

Verificador: criterio de aplicación de ACLs en interfaces.

Paso 6 — Configurar pc1 y srv1: IP y puerta de enlace ≈10 min

Asignar IP y puerta de enlace a pc1 (LAN) y srv1 (DMZ).

Comando exacto (desde el host de la estación):

ip netns exec lab-srv1 ip route add default via 172.16.5.1

Salida real: pc1 192.168.10.10/24, srv1 172.16.5.10/24, ambos con default gw hacia r1.

Verificación: ip netns exec lab-pc1 ip addr show eth0 muestra inet 192.168.10.10/24 y ruta default via 192.168.10.1.

Error típico: puerta de enlace incorrecta o interfaz no levantada. Corrección: verificar con ip addr show y ip route.

Verificador: criterio de direccionamiento de hosts.

Paso 7 — Verificar política de zonas (tests de ACL) ≈10 min

Confirmar que las ACLs aplican correctamente: LAN→WAN TCP sí, LAN→DMZ web sí, DMZ→LAN no, WAN→LAN no.

Comando exacto (desde el host de la estación):

# pc1 -> isp:80 (LAN→WAN, permitido)
ip netns exec lab-pc1 timeout 5 bash -c "< /dev/tcp/10.0.0.2/80 && echo OPEN || echo CLOSED"

# pc1 -> srv1:80 (LAN→DMZ web, permitido)
ip netns exec lab-pc1 timeout 5 bash -c "< /dev/tcp/172.16.5.10/80 && echo OPEN || echo CLOSED"

# srv1 -> pc1:22 (DMZ→LAN, denegado)
ip netns exec lab-srv1 timeout 3 bash -c "< /dev/tcp/192.168.10.10/22 && echo OPEN || echo CLOSED"

# isp -> pc1:22 (WAN→LAN, denegado)
ip netns exec lab-isp timeout 3 bash -c "< /dev/tcp/192.168.10.10/22 && echo OPEN || echo CLOSED"

Salida real:

OPEN
OPEN
exit=124 (timeout = denegado)
exit=124 (timeout = denegado)

Verificación: LAN→WAN y LAN→DMZ web = OPEN; DMZ→LAN y WAN→LAN = timeout (denegado por ACL).

Error típico: usar ping (ICMP) para testear; el retorno ICMP no tiene stateful established en este lab. Corrección: testear con TCP (puerto 80, 22, etc.).

Verificador: criterio de política de zonas y ACLs.

Paso 8 — Verificar tráfico de retorno (established) en nftables ≈10 min

Confirmar que el tráfico de retorno de conexiones iniciadas desde LAN se permite (regla established en ACL-WAN-LAN y ACL-DMZ-LAN).

Comando exacto:

ip netns exec lab-r1 nft list ruleset | grep -A5 "chain acl_ACL"

Salida real (contadores después de tests):

chain acl_ACL_LAN_DMZ_in {
    ip saddr 192.168.10.0/24 ip daddr 172.16.5.0/24 tcp dport 80 counter packets 4 bytes 216 accept
    ip saddr 192.168.10.0/24 ip daddr 10.0.0.0/30 counter packets 4 bytes 216 accept
    ip saddr 192.168.10.0/24 ip daddr 172.16.5.0/24 counter packets 0 bytes 0 drop
    counter packets 0 bytes 0 drop
}
chain acl_ACL_DMZ_LAN_in {
    ip saddr 172.16.5.0/24 ip daddr 192.168.10.0/24 ct state established,related meta l4proto tcp counter packets 2 bytes 112 accept
    ip saddr 172.16.5.0/24 ip daddr 192.168.10.0/24 counter packets 3 bytes 180 drop
    counter packets 0 bytes 0 drop
}
chain acl_ACL_WAN_LAN_in {
    ip saddr 10.0.0.0/30 ip daddr 192.168.10.0/24 ct state established,related meta l4proto tcp counter packets 2 bytes 112 accept
    ip saddr 10.0.0.0/30 ip daddr 192.168.10.0/24 counter packets 3 bytes 180 drop
    counter packets 0 bytes 0 drop
}

Verificación: contadores ct state established en ACL-WAN-LAN (2 pkts) y ACL-DMZ-LAN (2 pkts) = tráfico de retorno permitido. Denegaciones en 3 pkts cada una = conexiones nuevas bloqueadas.

Error típico: no verificar nftables y asumir que funciona. Corrección: siempre revisar contadores reales.

Verificador: criterio de tráfico de retorno (established).
