Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Valor: 5,0 (5 criterios × 1,0, automáticos) · Tiempo estimado: 60 minutos · Individual.

Objetivo

Tu estación trae una red pequeña de fábrica, sin nada configurado: un router (r1), un switch (sw1), dos PCs (pc1, pc2) y el extremo del proveedor (isp). Como cuando abres la caja de un dispositivo nuevo, tu trabajo es dejarla lista y segura:

  1. renombrar los dispositivos con la nomenclatura del curso,
  2. poner el banner de acceso restringido,
  3. apagar los puertos que no se usan,
  4. aplicar el hardening de red del router, y
  5. dejar la gestión remota segura (solo SSH, secretos cifrados).

La CLI de los dispositivos (netcli) imita Cisco IOS: enable, configure terminal, interface …, show running-config… Cada comando se aplica de verdad sobre el kernel Linux de la estación y se guarda con write memory.

Topología

                        (WAN)
                    isp ── eth0
                           │
                     eth1 ─┴─ r1  (eth2: sin usar)
                           │
                     gi0/0 ─┴─ sw1
                     gi0/1 ─── pc1
                     gi0/2 ─── pc2
                     gi0/3 ─── (sin usar)
                     gi0/4 ─── (sin usar)

Cómo empezar

En la terminal de tu estación:

mi-espacio      # te muestra la topología y los comandos
netcli r1       # consola del router (empiezas en modo usuario: r1>)

Dentro de netcli:

ComandoQué hace
enablepasa a modo privilegiado (r1#)
configure terminalmodo de configuración (r1(config)#)
interface eth2configura esa interfaz
end / exitsale del modo actual
write memoryguarda la configuración
show running-configmuestra la configuración viva
show ip interface briefestado de las interfaces

Los 5 criterios y cómo cumplirlos

1) hostnames — nombres normalizados

El router debe llamarse R1-HEP y el switch SW1-HEP (nomenclatura <función><número>-HEP):

netcli r1
r1> enable
r1# configure terminal
r1(config)# hostname R1-HEP
R1-HEP(config)# end

Repite en sw1 con hostname SW1-HEP.

2) banner — aviso de acceso restringido

Ambos dispositivos deben mostrar un banner que contenga el texto Acceso restringido. En netcli, el delimitador del banner es el primer y último carácter del argumento (aquí usamos #):

R1-HEP(config)# banner motd #Acceso restringido - solo personal autorizado#

Lo mismo en sw1. Al volver a entrar con netcli r1 verás el banner.

3) puertos_apagados — shutdown de lo que no se usa

Un puerto sin cable conectado no debe quedar «up»: se apaga administrativamente, como en un switch real.

R1-HEP(config)# interface eth2
R1-HEP(config-if)# shutdown
R1-HEP(config-if)# end
SW1-HEP(config)# interface gi0/3
SW1-HEP(config-if)# shutdown
SW1-HEP(config-if)# exit
SW1-HEP(config)# interface gi0/4
SW1-HEP(config-if)# shutdown
SW1-HEP(config-if)# end

Verifica con show ip interface brief: los tres deben decir administratively down (no basta con que no tengan cable).

4) hardening_ip — que el router no ayude al atacante

El router viene, como IOS de fábrica, emitiendo ICMP redirects y aceptando source routes: dos comportamientos que un atacante puede usar para redirigir tráfico. Apágalos:

R1-HEP(config)# no ip redirects
R1-HEP(config)# no ip source-route

Estos dos sí se comprueban en el kernel de la estación (send_redirects=0, accept_source_route=0): no basta con escribirlos, quedan desactivados de verdad.

5) gestion_segura — acceso de gestión blindado

En ambos dispositivos:

R1-HEP(config)# line vty
R1-HEP(config-line)# transport input ssh
R1-HEP(config-line)# exit
R1-HEP(config)# enable secret ClaveSegura123
R1-HEP(config)# username admin secret AdminSegura123
R1-HEP(config)# service password-encryption
R1-HEP(config)# end
R1-HEP# write memory
  • transport input ssh: la línea VTY solo acepta SSH (nada de telnet).
  • enable secret y username … secret: netcli los guarda cifrados (hash SHA-512, $6$…), nunca en claro — míralo en show running-config.
  • service password-encryption: activa el cifrado de secretos en la configuración.

Repite el bloque completo en sw1.

Comprobar y entregar

R1-HEP# show running-config     # revisa hostname, banner, secretos ($6$…), vty
SW1-HEP# show running-config
$ revisar                       # desde la terminal de la estación (fuera de netcli)

revisar le pide al servidor que evalúe tu estación desde fuera: no cuenta lo que digas tú, sino el estado real de tus interfaces, tus sysctls y tu configuración. Puedes ejecutarlo las veces que quieras.

Notas de la simulación (honestidad ante todo)

  • Los dispositivos son kernel Linux real (namespaces + veth + puentes 802.1Q + nftables); la CLI es un subconjunto IOS. No hay STP, ni CDP, ni protocolos de enrutamiento dinámico en este lab.
  • hostname/banner viven en la configuración del dispositivo (como el startup-config de IOS); el hardening (criterios 3 y 4) se mira directo en el kernel.
  • Los «secretos» del lab son de práctica: usa los de la guía o inventa los tuyos, pero nunca uses contraseñas reales tuyas en un laboratorio.
