Lab 1 — Configuración básica y hardening de dispositivos

Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Lab 1 · Tiempo estimado: 60 min · Semana: S1

Objetivo

La estación trae una red de fábrica (router r1, switch sw1, dos PCs y un extremo de WAN) sin nada configurado. Debes ponerle nombre a los dispositivos, banner de acceso restringido, apagar los puertos sin usar y aplicar el hardening de red (no redirects, no source-route) y de gestión (solo SSH en VTY, secretos cifrados, service password-encryption).

Guía verificada: esta guía se ejecutó sobre una estación desechable (oco-tmp-lab01-station, imagen labs/hep-redes-lab01:1.0.0). Todas las salidas de configuración son reales de esa estación.

Topología de fábrica

           (WAN)           (LAN)
         isp eth0 ========= eth0 r1 eth1 ========= gi0/0 sw1
                                          |         |
                                      gi0/1       gi0/2
                                      pc1         pc2

Dispositivos: r1 (router), sw1 (switch), pc1, pc2 (hosts), isp (extremo WAN).

CLI (netcli, estilo IOS)

Entra a un dispositivo con netcli <dispositivo> (p. ej. netcli r1).

ComandoQué hace

Guía paso a paso (10 pasos)

Paso 1 — Verificar estado inicial de fábrica ≈5 min

Objetivo: confirmar que la estación llega sin configurar (hostname de fábrica, sin banner, sin secretos, Telnet habilitado, puertos sin usar up).

Comando exacto (en netcli r1):

enable
show running-config
show ip interface brief
exit

Salida real (estación oco-tmp-lab01-station):

r1# ! configuración en vivo de r1 (netcli sobre kernel Linux)
hostname r1
line vty
 transport input all
r1# Interface              IP-Address      OK? Method Status                Protocol
eth0                   unassigned      YES manual up                     up
eth1                   unassigned      YES manual up                     up
eth2                   unassigned      YES manual up                     up

Verificación: hostname r1 (de fábrica), transport input all (Telnet habilitado), sin enable secret, sin banner motd, sin IPs configuradas.

Error típico: asumir que la estación ya tiene configuración. Corrección: esta es la línea base; todo se configura desde cero.

Verificador: criterio de hardening (detecta falta de secretos y SSH).

Paso 2 — Verificar estado inicial de sw1 ≈5 min

Objetivo: confirmar que sw1 llega sin configurar (todos los puertos en VLAN 1, sin VLANs con nombre, sin seguridad).

Comando exacto (en netcli sw1):

Salida real:

sw1# VLAN Name                             Status    Ports
1     VLAN01                           active    gi0/0,gi0/1,gi0/2

Verificación: hostname sw1, transport input all, solo VLAN 1, todos los puertos en VLAN 1 por defecto.

Error típico: no verificar el estado inicial antes de empezar. Corrección: siempre documentar el estado de fábrica.

Verificador: criterios de VLANs y seguridad en switch.

Paso 3 — Configurar r1: nombre, banner y seguridad básica ≈10 min

Objetivo: poner nombre de convención, banner restrictivo, contraseña de modo privilegiado cifrada, usuario admin con secreto, cifrado de contraseñas, solo SSH en VTY, consola protegida.

Comando exacto (en netcli r1):

enable
configure terminal
hostname R1-HEP
banner motd #Acceso restringido - Lab 01#
enable secret ClaveSegura123
username admin secret AdminSegura123
service password-encryption
line vty
transport input ssh
line console 0
password ConsolaSegura123
exit
end
write memory

Paso 4 — Configurar r1: direccionamiento de interfaces y rutas ≈10 min

Objetivo: asignar IPs a eth0 (enlace WAN hacia isp) y eth1 (enlace LAN hacia sw1), y agregar ruta estática hacia la LAN de usuarios.

Comando exacto (en netcli r1):

interface eth0
ip address 10.0.0.1 255.255.255.252
exit
interface eth1
ip address 10.0.0.5 255.255.255.252
exit
ip route 192.168.10.0 255.255.255.0 10.0.0.6
end
write memory
show running-config
show ip interface brief
show ip route

Salida real:

R1-HEP# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
eth0                   10.0.0.1/30     YES manual up                     up
eth1                   10.0.0.5/30     YES manual up                     up
eth2                   unassigned      YES manual up                     up
R1-HEP# show ip route
C  10.0.0.0/30 directamente conectada, eth0 (conectada, 10.0.0.1)
C  10.0.0.4/30 directamente conectada, eth1 (conectada, 10.0.0.5)
O  192.168.10.0/24 via 10.0.0.6, eth1

Verificación: show ip interface brief muestra eth0 y eth1 con IP y estado up/up; show ip route muestra rutas conectadas y estática.

Error típico: usar máscara incorrecta que solape con otra subred, o olvidar la ruta estática. Corrección: verificar con show ip route y show ip interface brief.

Verificador: criterios de direccionamiento y conectividad.

Paso 6 — Configurar sw1: VLANs y puertos de acceso ≈10 min

Objetivo: crear VLAN 10 (usuarios) y VLAN 20 (servicios), asignar puertos de acceso a pc1 y pc2.

Comando exacto (en netcli sw1):

vlan 10
name USUARIOS
exit
vlan 20
name SERVICIOS
exit
interface gi0/1
switchport access vlan 10
exit
interface gi0/2
switchport access vlan 20
exit
end
write memory
show vlan brief

Salida real:

SW1-HEP# show vlan brief
VLAN Name                             Status    Ports
1     VLAN01                           active
10    USUARIOS                         active    gi0/1
20    SERVICIOS                        active    gi0/2

Verificación: show vlan brief muestra VLAN 10 y 20 con nombre y puertos asignados.

Error típico: crear VLANs sin nombre o asignar puertos a la VLAN incorrecta. Corrección: verificar con show vlan brief.

Verificador: criterio de VLANs configuradas con nombre.

Paso 7 — Configurar sw1: troncal 802.1Q hacia r1 y apagar puertos sin usar ≈10 min

Objetivo: configurar gi0/0 como troncal 802.1Q hacia r1 transportando VLANs 10 y 20, y apagar puertos gi0/3, gi0/4, gi0/5 sin usar.

Comando exacto (en netcli sw1):

interface gi0/0
switchport mode trunk
switchport trunk allowed vlan 10,20
exit
interface gi0/3
shutdown
exit
interface gi0/4
shutdown
exit
interface gi0/5
shutdown
exit
end
write memory
show running-config | include trunk|shutdown
show interfaces trunk

Salida real:

SW1-HEP# show running-config
interface gi0/0
 switchport mode trunk
 switchport trunk allowed vlan 10,20
interface gi0/3
 shutdown
interface gi0/4
 shutdown
interface gi0/5
 shutdown

Verificación: show running-config muestra switchport mode trunk en gi0/0 con VLANs 10,20 permitidas, y shutdown en gi0/3-5.

Error típico: configurar troncal solo en un extremo o permitir VLANs incorrectas. Corrección: verificar switchport trunk allowed vlan en ambos extremos.

Verificador: criterio de troncales 802.1Q operando y puertos sin usar apagados.

Paso 8 — Configurar PCs: IP y puerta de enlace ≈10 min

Objetivo: asignar IP y puerta de enlace a pc1 (VLAN 10) y pc2 (VLAN 20).

Comando exacto (desde el host de la estación):

ip netns exec lab-pc1 ip addr add 192.168.10.10/24 dev eth0
ip netns exec lab-pc1 ip link set eth0 up
ip netns exec lab-pc1 ip route add default via 192.168.10.1
ip netns exec lab-pc2 ip addr add 192.168.10.11/24 dev eth0
ip netns exec lab-pc2 ip link set eth0 up
ip netns exec lab-pc2 ip route add default via 192.168.10.1

Salida real: comandos sin errores; los PCs quedan con IP configurada y ruta por defecto.

Verificación: ip netns exec lab-pc1 ip addr show eth0 muestra inet 192.168.10.10/24 y ip route muestra default via 192.168.10.1.

Error típico: puerta de enlace incorrecta o interfaz no levantada con ip link set eth0 up. Corrección: verificar con ip addr show y ip route.

Verificador: criterio de direccionamiento de hosts.

Paso 9 — Verificación final de configuración ≈10 min

Objetivo: confirmar que toda la configuración está aplicada correctamente antes de ejecutar el verificador.

Comando exacto:

netcli r1    show running-config
netcli r1    show ip interface brief
netcli sw1   show running-config
netcli sw1   show vlan brief

Salida real: todos los dispositivos muestran hostname, banner, enable secret con hash $6$, service password-encryption, transport input ssh, interfaces con IP, VLANs con nombre, troncal configurado.

Verificación: ninguna salida muestra valores de fábrica (hostname r1/sw1, transport input all, sin secretos).

Error típico: algún dispositivo queda con configuración de fábrica. Corrección: repetir el paso correspondiente.

Verificador: todos los criterios automáticos.

Paso 10 — Ejecutar el verificador automático ≈10 min

Objetivo: ejecutar revisar para que el servidor evalúe la estación y reporte el veredicto.

Comando exacto (en la estación):

revisar

Salida esperada: el servidor evalúa los criterios automáticos y reporta cuántos están en verde.

Verificación: todos los criterios muestran [OK]. Resultado: X de Y criterios en verde.

Error típico: algún criterio en rojo. Corrección: revisar el detalle del criterio fallante y aplicar el paso correspondiente nuevamente.

Verificador: criterios automáticos del lab (100 pts).
