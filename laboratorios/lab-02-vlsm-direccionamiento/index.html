Lab 2 — VLSM y direccionamiento

Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Lab 2 · Tiempo estimado: 75 min · Semana: S2

Objetivo

Planifica con VLSM la red 10.10.0.0/22 para tres LANs (60, 28 y 12 hosts) y el enlace WAN entre dos routers, aplica las direcciones en los routers y los hosts, instala las rutas estáticas y comprueba la conectividad extremo a extremo.

Guía verificada: esta guía se ejecutó sobre una estación desechable (oco-tmp-lab02-station, imagen labs/hep-redes-lab02:1.0.0). Todas las salidas son reales de esa estación. Conectividad verificada: 0% de pérdida en todos los pings.

Objetivo: confirmar que los routers llegan sin configurar (sin IPs, sin rutas, sin secretos, Telnet habilitado).

show running-config
show ip interface brief
exit

Error típico: no documentar el estado inicial. Corrección: siempre verificar el estado de fábrica antes de configurar.

Paso 4 — Configurar r1: interfaz WAN (eth0) y LAN A (eth1) ≈10 min

Objetivo: asignar IP a eth0 (enlace WAN hacia r2) y eth1 (LAN A hacia pc1).

Comando exacto (en netcli r1):

ip address 10.10.0.101 255.255.255.252
exit
interface eth1
ip address 10.10.0.1 255.255.255.192
exit
end
write memory

Verificación: eth0 con 10.10.0.101/30 y eth1 con 10.10.0.1/26, ambas up/up.

Error típico: usar máscara incorrecta que solape con otra subred del plan VLSM. Corrección: verificar con show ip interface brief.

Verificador: criterio de direccionamiento VLSM sin solapamientos.

Paso 8 — Configurar PCs y servidor: IP y puerta de enlace ≈10 min

Objetivo: asignar IP y puerta de enlace a pc1, pc2 y srv1.

Comando exacto (desde el host de la estación):

# PC1 (LAN A: 10.10.0.0/26, gw 10.10.0.1)
ip netns exec lab-pc1 ip addr add 10.10.0.10/26 dev eth0
ip netns exec lab-pc1 ip link set eth0 up
ip netns exec lab-pc1 ip route add default via 10.10.0.1

# PC2 (LAN B: 10.10.0.64/27, gw 10.10.0.65)
ip netns exec lab-pc2 ip addr add 10.10.0.66/27 dev eth0
ip netns exec lab-pc2 ip link set eth0 up
ip netns exec lab-pc2 ip route add default via 10.10.0.65

# SRV1 (LAN C: 10.10.0.96/28, gw 10.10.0.97)
ip netns exec lab-srv1 ip addr add 10.10.0.98/28 dev eth0
ip netns exec lab-srv1 ip link set eth0 up
ip netns exec lab-srv1 ip route add default via 10.10.0.97

Salida real: comandos sin errores; todos los hosts quedan con IP y ruta por defecto configuradas.

Verificación: ip netns exec lab-pc1 ip addr show eth0 muestra inet 10.10.0.10/26.

Error típico: puerta de enlace incorrecta o interfaz no levantada. Corrección: verificar con ip addr show y ip route.

Verificador: criterio de direccionamiento de hosts.
