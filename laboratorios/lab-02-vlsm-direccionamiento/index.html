Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Valor: 5,0 (5 criterios × 1,0) · Tiempo estimado: 75 minutos · Individual.

Objetivo

Tu estación tiene dos routers (r1, r2) unidos por un enlace WAN y tres LANs: A con pc1, B con pc2 y C con el servidor srv1. Nada tiene direcciones. Vas a planificar el direccionamiento con VLSM a partir de 10.10.0.0/22, aplicarlo en los routers con netcli y en los hosts con su consola Linux, instalar las rutas estáticas y demostrar conectividad extremo a extremo.

El reto VLSM

Reparte 10.10.0.0/22 sin desperdiciar (de mayor a menor):

SegmentoHosts necesariosPrefijo que le corresponde
LAN A (pc1, detrás de r1)60/26 → 10.10.0.0/26 (62 útiles)
LAN B (pc2, detrás de r2)28/27 → 10.10.0.64/27 (30 útiles)
LAN C (srv1, detrás de r2)12/28 → 10.10.0.96/28 (14 útiles)
WAN r1–r22/30 → 10.10.0.124/30 (2 útiles)

El verificador de la WAN acepta cualquier /30 válida y dentro del /22 cuyos dos extremos compartan subred; el resto del plan es fijo para que todos comparen resultados.

Routers con netcli

netcli r1
r1> enable
r1# configure terminal
r1(config)# interface eth0
r1(config-if)# ip address 10.10.0.125 255.255.255.252
r1(config-if)# no shutdown
r1(config-if)# exit
r1(config)# interface eth1
r1(config-if)# ip address 10.10.0.1 255.255.255.192
r1(config-if)# no shutdown
r1(config-if)# exit
r1(config)# ip route 10.10.0.64 255.255.255.224 10.10.0.126
r1(config)# ip route 10.10.0.96 255.255.255.240 10.10.0.126
r1(config)# end
r1# write memory

En r2 lo análogo: eth0 10.10.0.126/30, eth1 10.10.0.65/27, eth2 10.10.0.97/28, y la ruta de vuelta:

r2(config)# ip route 10.10.0.0 255.255.255.192 10.10.0.125

Verifica con show ip interface brief y show ip route en ambos.

Hosts (consola Linux)

Los PCs no hablan IOS: entra a su consola y usa los comandos de Linux.

netcli pc1
[pc1] $ ip addr add 10.10.0.10/26 dev eth0
[pc1] $ ip route add default via 10.10.0.1
[pc1] $ ping 10.10.0.1          # tu gateway
[pc1] $ exit

Repite con pc2 (10.10.0.66/27, gw 10.10.0.65) y srv1 (10.10.0.98/28, gw 10.10.0.97).

Comprobación final

Desde pc1:

[pc1] $ ping 10.10.0.66      # LAN B, cruzando la WAN
[pc1] $ ping 10.10.0.98      # LAN C
[pc1] $ exit
$ revisar

Los criterios se leen directo del kernel (direcciones, máscaras, rutas y pings reales): no cuentan los show que copies y peguen, sino la red funcionando.

Errores típicos que este lab detecta

  • Máscara puesta «al ojo» (un /24 en todas partes): sobra espacio y las LANs se solapan con la WAN.
  • Rutas hacia la subred equivocada o con el vecino mal puesto.
  • PC sin puerta de enlace: el ping al gateway funciona pero al resto no.
