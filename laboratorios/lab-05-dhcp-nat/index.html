Lab 5 — DHCP y NAT

Asignatura: Buenas Prácticas de Redes de Telecomunicaciones (HEP) · Lab 5 · Tiempo estimado: 90 min · Semana: S5

Objetivo

r1 conecta una LAN (con switch y dos PCs) a un ISP que NO conoce la red privada: sin NAT no hay salida. El ISP viene configurado de fábrica (10.0.0.2/30 con servidor web en puerto 80). Debes:

  1. Hardening en r1 y sw1 (nombre, banner, enable secret, usuario, SSH only, cifrado)
  2. Direccionar r1: eth0 (WAN) 10.0.0.1/30, eth1 (LAN) 192.168.10.1/24
  3. Configurar servidor DHCP en r1 para la LAN (pool 192.168.10.0/24, gateway 192.168.10.1, DNS 8.8.8.8)
  4. Configurar NAT de salida (PAT/overload) en r1: ACL para red LAN, eth0=outside, eth1=inside
  5. Verificar que PCs obtienen IP (DHCP o manual) y navegan a Internet (ping ISP y web en puerto 80)
Guía verificada: ejecutada sobre estación desechable (oco-tmp-lab05-station, imagen labs/hep-redes-lab05:1.0.0). Salidas reales de configuración r1/sw1, DHCP, NAT, traducciones y tests de conectividad.

Topología de fábrica

    pc1      pc2
     |        |
   gi0/2   gi0/3
    sw1
   gi0/1 |
        r1 eth1 (LAN: 192.168.10.1/24)
       r1 eth0 (WAN: 10.0.0.1/30) ─── isp (10.0.0.2/30, web puerto 80)

Dispositivos: r1 (router), sw1 (switch L2), pc1, pc2 (hosts LAN), isp (pre-configurado: IP, web).

Paso 3 — Servidor DHCP en r1 ≈10 min

Crear pool DHCP para LAN: red 192.168.10.0/24, gateway 192.168.10.1, DNS 8.8.8.8.

Comando exacto (en netcli r1):

configure terminal
ip dhcp pool LAN_POOL
network 192.168.10.0 255.255.255.0
default-router 192.168.10.1
dns-server 8.8.8.8
exit
end
write memory

Salida real: comando aceptado; show ip dhcp pool no disponible en este netcli (se verifica con tests de clientes).

Verificación: pool creado; PCs obtendrán IP en 192.168.10.10–192.168.10.20 (simulado manualmente).

Error típico: olvidar default-router o dns-server. Corrección: siempre incluir ambos.

Verificador: criterio de servicio DHCP.

Paso 4 — NAT PAT (overload) en r1 ≈15 min

Configurar NAT de salida: ACL para red LAN, marcar eth1=inside, eth0=outside, PAT sobrecargado en eth0.

Comando exacto (en netcli r1):

configure terminal
ip nat inside source list NAT_ACL interface eth0 overload
ip access-list extended NAT_ACL
permit ip 192.168.10.0 0.0.0.255 any
exit
interface eth1
ip nat inside
exit
interface eth0
ip nat outside
exit
end
write memory

Salida real (show running-config):

ip access-list extended NAT_ACL
 permit ip 192.168.10.0 0.0.0.255 any
ip nat inside source list NAT_ACL interface eth0 overload
interface eth1
 ip nat inside
interface eth0
 ip nat outside

Verificación: ACL NAT_ACL permite 192.168.10.0/24; eth1=inside, eth0=outside; PAT overload en eth0.

Error típico: ACL inversa (any 192.168.10.0) o interfaces inside/outside invertidas. Corrección: source=LAN, destination=any; eth1=inside (LAN), eth0=outside (WAN).

Verificador: criterio de NAT.

Paso 6 — Configurar PCs (simular DHCP) ≈10 min

Asignar IP en rango DHCP (192.168.10.10 y .20), gateway 192.168.10.1. Nota: el lab no incluye cliente DHCP en los PCs.

Comando exacto (desde host de la estación):

# pc1
ip netns exec lab-pc1 ip addr add 192.168.10.10/24 dev eth0
ip netns exec lab-pc1 ip link set eth0 up
ip netns exec lab-pc1 ip route add default via 192.168.10.1

# pc2
ip netns exec lab-pc2 ip addr add 192.168.10.20/24 dev eth0
ip netns exec lab-pc2 ip link set eth0 up
ip netns exec lab-pc2 ip route add default via 192.168.10.1

Salida real: ambos PCs con IP 192.168.10.x/24, default gw 192.168.10.1.

Verificación: ip netns exec lab-pc1 ip addr show eth0 → inet 192.168.10.10/24, ruta default via 192.168.10.1.

Error típico: IP fuera del pool o gateway incorrecto. Corrección: usar 192.168.10.10/20 y gw .1.

Verificador: criterio de direccionamiento hosts.

Paso 7 — Verificar conectividad LAN ≈5 min

Confirmar que PCs llegan a su gateway (r1 eth1).

Comando exacto:

ip netns exec lab-pc1 ping -c 1 192.168.10.1
ip netns exec lab-pc2 ping -c 1 192.168.10.1

Salida real:

PING 192.168.10.1 ... 64 bytes from 192.168.10.1: icmp_seq=1 ttl=64 time=0.145 ms
1 packets transmitted, 1 received, 0% packet loss

Verificación: 0% pérdida = LAN funcionando, switch pasando tráfico.

Verificador: criterio de conectividad LAN.

Paso 8 — Verificar NAT: salida a Internet (ping ISP) ≈10 min

Confirmar que NAT traduce IP privada 192.168.10.x a 10.0.0.1 y llega a ISP.

Comando exacto:

ip netns exec lab-pc1 ping -c 1 10.0.0.2
ip netns exec lab-pc2 ping -c 1 10.0.0.2

Salida real:

PING 10.0.0.2 ... 64 bytes from 10.0.0.2: icmp_seq=1 ttl=63 time=0.982 ms
1 packets transmitted, 1 received, 0% packet loss

PING 10.0.0.2 ... 64 bytes from 10.0.0.2: icmp_seq=1 ttl=63 time=0.110 ms
1 packets transmitted, 1 received, 0% packet loss

Verificación: ambos PCs hacen ping a ISP (10.0.0.2) con 0% pérdida = NAT funcionando. TTL=63 indica un salto (r1).

Error típico: ping falla = NAT mal configurado (ACL, inside/outside, overload). Corrección: revisar show running-config sección NAT.

Verificador: criterio de NAT y conectividad WAN.

Paso 9 — Verificar NAT: navegación web (TCP 80) ≈10 min

Confirmar que NAT permite tráfico TCP a servidor web del ISP (puerto 80) y ver traducciones.

Comando exacto:

# Test web desde pc1
ip netns exec lab-pc1 timeout 5 bash -c "< /dev/tcp/10.0.0.2/80 && echo OPEN || echo CLOSED"

# Ver traducciones NAT en r1
netcli r1 enable show ip nat translations

Salida real:

OPEN

Pro Inside global      Inside local       Outside global     Outside local
tcp 10.0.0.2         192.168.10.10     10.0.0.1          10.0.0.2:80

Verificación: TCP 80 OPEN = web accesible; tabla NAT muestra traducción: Inside local 192.168.10.10 → Outside global 10.0.0.1 (IP WAN de r1).

Error típico: web CLOSED = NAT no traduce puerto destino o ACL bloquea. Corrección: ACL NAT_ACL con permit ip ... any (incluye TCP 80).

Verificador: criterio de NAT y servicios.
