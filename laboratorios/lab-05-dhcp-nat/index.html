Objetivo

La red interna (pc1 y pc2 tras sw1) debe levantarse sola y salir a Internet sin exponerse. El ISP (10.0.0.2, con servidor web) no conoce tu red privada: si no traduces, no hay salida; y gracias al NAT tampoco pueden entrar. Montarás:

  1. DHCP en r1 para la LAN: rango 192.168.10.100–.150, gateway 192.168.10.1, DNS 10.0.0.2.
  2. NAT overload (PAT): la LAN sale con la IP pública 10.0.0.1.
 pc1 ── gi0/2 ┐
 pc2 ── gi0/3 │ sw1 ── gi0/1 ── eth1 r1 eth0 ── ISP 10.0.0.2 (web)

Paso 1 — Interfaces del router (con su rol de NAT)

netcli r1
r1> enable
r1# configure terminal
r1(config)# interface eth0
r1(config-if)# ip address 10.0.0.1 255.255.255.252
r1(config-if)# no shutdown
r1(config-if)# ip nat outside
r1(config-if)# exit
r1(config)# interface eth1
r1(config-if)# ip address 192.168.10.1 255.255.255.0
r1(config-if)# no shutdown
r1(config-if)# ip nat inside
r1(config-if)# exit

Paso 2 — El pool de DHCP

r1(config)# ip dhcp pool LAN
r1(config-dhcp)# network 192.168.10.0 255.255.255.0
r1(config-dhcp)# default-router 192.168.10.1
r1(config-dhcp)# dns-server 10.0.0.2
r1(config-dhcp)# range 192.168.10.100 192.168.10.150
r1(config-dhcp)# exit

Al salir del pool, el DHCP del router arranca solo. Compruébalo pidiendo IP desde un PC:

netcli pc1
[pc1] $ busybox udhcpc -i eth0 -f -n -q -t 10 -T 1 -s /usr/share/udhcpc/default.script
[pc1] $ ip addr show eth0        # te llegó una IP del rango .100–.150
[pc1] $ ip route                 # default via 192.168.10.1
[pc1] $ exit

Haz lo mismo en pc2.

Paso 3 — El NAT overload

El NAT necesita saber qué tráfico traducir: se lo dices con un ACL.

r1(config)# ip access-list extended LAN-NAT
r1(config-ext-nacl)# permit ip 192.168.10.0 0.0.0.255 any
r1(config-ext-nacl)# exit
r1(config)# ip nat inside source list LAN-NAT interface eth0 overload
r1(config)# end
r1# write memory

overload = PAT: muchos equipos privados salen por la única IP pública cambiando el puerto.

Paso 4 — Comprobar

[pc1] $ busybox wget -q -O- http://10.0.0.2/    # HTTP 200: sales por el NAT
$ ip netns exec lab-isp ping -c1 192.168.10.100   # debe FALLAR: no hay ruta ni NAT inverso
$ revisar

Y en el router:

r1# show ip nat translations
r1# show access-lists

El verificador genera tráfico y mira la tabla conntrack del router: las traducciones deben mostrar tu IP pública. También comprueba que el ISP no alcanza la IP privada de pc1 con la salida funcionando.

Errores típicos

  • ip nat inside en la WAN y outside en la LAN (al revés): nada sale.
  • Pool sin range: el DHCP arranca pero no reparte.
  • El ACL del NAT con máscara de red en vez de wildcard (255.255.255.0 en vez de 0.0.0.255): la regla de masquerade no coincide con nada.
  • Olvidar que el ISP no tiene tu ruta: si «funciona» sin NAT, revisa que no le hayas puesto rutas al ISP.
